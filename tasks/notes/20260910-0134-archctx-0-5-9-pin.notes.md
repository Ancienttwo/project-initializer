## Design Decisions

- `REFACTOR_PROVIDER_VERSION` moves with `ARCHCTX_REQUIRED_VERSION` even though the refactor
  stages do not consume `priorCommittedApplies`. Both constants resolve the same package-local
  install through `resolvePackageLocalArchctx`, and the refactor policy reader asserts exact
  equality, so leaving it at 0.5.8 would fail-close every refactor stage against a package that
  no longer exists at that version.
- The required-feature entry is added in the same slice as the pin move. Requiring the feature
  before the pin would fail every projection closed; moving the pin without the feature would
  leave a provider that silently drops `priorCommittedApplies` indistinguishable from 0.5.8.
- `assets/workflow-contract.v1.json` and `.ai/harness/workflow-contract.json` are unchanged: they
  carry no archctx version, so they are not pin surfaces.
- The `declares nothing when the provider does not report the prior commit` case in
  `tests/architecture-projection-late-write-receipt.test.ts` keeps its coverage under 0.5.9. The
  upstream contract omits `priorCommittedApplies` rather than emitting `[]`, so absence stays a
  legal 0.5.9 answer; only the comment that attributed the absence to 0.5.8 was corrected.

## Incident-Shape Coverage Gap

The unit fixtures drive `priorCommittedApplies` through a stubbed `RunArchctxProcess`, so no test
exercises the real incident: a real archctx apply that commits the manifest, is killed before it
answers, and reports the commit on the retry.

An end-to-end reproduction was attempted and is not feasible against archctx 0.5.9. The kill must
land after the provider commits and before it returns, and 0.5.9 exposes no injection point for
that window -- its only environment surfaces are `ARCHCTX_CAPABILITIES_SCHEMA_VERSION` and
`ARCHCTX_FEATURES`, both internal build constants rather than runtime hooks, so the kill instant
cannot be made deterministic. Driving the kill from the harness timeout instead only proves the
timeout path, because a sub-second deadline terminates the attempt before any commit.

What was proven against the real provider instead:

- `node node_modules/archctx/bin/archctx.mjs capabilities --json` on the installed 0.5.9 lists
  `projection-prior-committed-applies-v1`.
- `bun src/cli/index.ts architecture-projection status --json` reports
  `"reason": "exact package-local capability handshake passed"` under the new required-feature set,
  so the real provider satisfies the stricter gate.
- Fail-closed direction, real binary: a copy of the installed 0.5.9 CLI with only the feature
  removed from its advertised list, resolved through `resolvePackageLocalArchctx`, is rejected with
  `archctx required feature set mismatch`. The copy was a throwaway probe and is not committed.

The gap that remains is the provider-side production of `priorCommittedApplies` after a real killed
apply. It closes when archctx offers a deterministic post-commit fault point, or when a real
incident is captured with its receipt.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Leave `REFACTOR_PROVIDER_VERSION` at 0.5.8 | Rejected | The refactor stages resolve the same package-local install; the pin would point at a version no longer on disk |
| Require the feature without moving the pin | Rejected | Fails every projection closed on 0.5.8, which is exactly why the goal was deferred |
| Drive the incident shape from the harness projection timeout | Rejected | A sub-second deadline kills the attempt before any commit, so it proves the timeout path rather than the late write |
| Patch a copy of the real 0.5.9 CLI to drop the feature and run the handshake | Chosen for the fail-closed direction | Gives real-binary rejection evidence without weakening the shipped install; probe not committed |
